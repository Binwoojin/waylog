## 2. 실행 환경

| 항목 | 값 |
|---|---|
| 백엔드 | Spring Boot 4.1, JDK 25.0.2, `local` 프로필 (H2 인메모리, MySQL 모드) |
| 프론트엔드 | Vite 개발 서버, `http://localhost:5173` (CORS 허용 오리진) |
| 브라우저 | Google Chrome headless, `playwright-core` 1.63 (프로젝트 의존성 아님, 검증용 스크립트에서만 사용) |
| 메일 | 로컬 SMTP 수신기(`aiosmtpd`, 포트 3025). 인증번호 메일을 받아 코드를 읽는 데만 사용 |
| 데이터 | 검증 직전 백엔드를 재기동해 H2를 비운 뒤, 테스트 계정 2개를 실제 가입 API로 생성 |
| 계정 | 계정 A(`verifyA`, 글·댓글 작성자), 계정 B(`verifyB`, 타인 역할). 이메일은 결과 파일에서 가렸다 |

**메일 수신기 예열 조건 (중요)**
- 백엔드 재기동 직후 **첫 인증번호 발송은 간헐적으로 500**이 났다. 백엔드 로그에 `SocketTimeoutException: Read timed out`이 찍혔고, 같은 수신기에 직접 보내면 1~2초에 성공했다.
- 두 번째 이후 발송은 모두 200이었다.
- 검증 스크립트는 **인증번호 발송 전에 한 번 예열 요청**을 보내고, 입력란이 여전히 비활성이면 발송을 한 번 더 누르도록 했다.
- 따라서 S1은 "예열 후 발송" 조건에서 통과한 결과다. **운영 SMTP에서의 발송 안정성은 검증하지 않았다.**

## 6. 이전 라운드 결과와 구분

이 문서의 결과와 별개로, 같은 프로젝트에는 다음 검증이 있다. 실행 방식이 다르므로 섞어서 보고하지 않는다.

- **실서버 기반 17개 흐름 중 15개 통과 (이전 라운드)**: 백엔드 수정 전 시점의 결과다. 나머지 2건(없는 콘텐츠 404, 타인 게시물 403)은 백엔드를 고친 뒤 확인했다.
- **모킹 기반 검증**: 모달 포커스 트랩, 포커스 복귀, 댓글 목록 로드, 빈 북마크 문구는 브라우저 안에서 Playwright 라우트로 API 응답을 가짜로 만든 뒤 확인했다. 실서버 데이터가 아니다.
- **지연 주입 기반 검증**: 북마크 더블 클릭 시 요청 1회만 나가는 것은 응답을 1초 늦춘 상태에서 확인했다. 실서버 응답 시간이 아니다.
