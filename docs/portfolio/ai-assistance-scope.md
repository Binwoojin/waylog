# Claude Code 보조 범위와 직접 판단·확인 범위

> **목적**: 포트폴리오에서 무엇을 Claude Code가 보조했고, 무엇을 사용자가 판단하고 확인했는지 구분한다.
> **기준**: 이 문서는 작업 세션의 대화 기록과 커밋 이력, 검증 결과 파일에 남은 사실만 근거로 한다. 기록에 없는 기여나 성과 수치는 만들지 않았다.
> **사용 방법**: 면접이나 이력서에 쓰기 전에 "직접 확인" 칸을 본인이 다시 확인한다. 확인하지 못한 항목은 이력서에 쓰지 않는다.

---

## 1. 구분 기준

| 구분 | 의미 |
|---|---|
| **Claude Code 보조** | 코드 작성, 파일 탐색, 테스트 작성과 실행, 에이전트 위임 등을 Claude Code가 수행한 부분 |
| **사용자 결정** | 우선순위, 기능의 방향, 승인, 보류 등 세션에서 사용자가 내린 판단 |
| **사용자 확인 필요** | 자동 검증으로 대체할 수 없어서 사용자가 직접 실행하거나 판단해야 하는 부분 |

## 2. 영역별 구분

| 영역 | Claude Code 보조 | 사용자 결정·요청 (세션 기록) | 사용자가 직접 확인할 것 |
|---|---|---|---|
| 프로젝트 방향 | 기존 PDCA 문서와 코드를 대조해 현황을 정리 | 포트폴리오 목적, 우선순위(핵심 기능 검증 우선) | 우선순위 설정이 맞는지 |
| 관리자 대시보드 | 설계 문서 작성, 구현, 테스트 | 리소스 범위 결정(Q-1~Q-7 답변), 정지는 기간제 로그인 차단으로 결정 | 실제 관리자 화면에서 흐름 확인 |
| 목업 제거와 실API 전환 | 목업 페이지 조사, 실API 연결 구현, 404 처리 | "실제 API로 연결"과 "미구현 기능 숨김" 선택 | 화면에서 빈 상태와 오류 상태 확인 |
| 인증 토큰·세션 | 토큰 흐름 구현, 경쟁 조건 수정, 테스트 | 메모리 보관 방식은 PDCA 설계 단계에서 선택지 비교 후 확정 | 로그인·로그아웃·새로고침 직접 확인 |
| 북마크·댓글 | 낙관적 갱신, 가드, 댓글 수 UPDATE, 회귀 테스트 | 공유 버튼 유지 여부 결정, 목록 카드 북마크 제거 승인 | 실제 계정으로 저장·댓글 흐름 확인 |
| 검증 체계 | 백엔드·프론트 테스트 작성, 실서버 검증 스크립트 작성 | 검증 범위 결정("실제 실행한 항목만 통과로 기록") | 검증 결과 문서의 미실행 항목 확인 |
| 커밋·push | 커밋 메시지 작성, 논리 단위 분리 | 커밋 방식 승인, push는 요청 시에만 수행 | push 여부 최종 결정 |
| 약관 검증 | 서버 검증 구현과 테스트 | "필수 동의 검증은 하고, 이력 저장은 별도"로 범위 분리 | 법적 고지 문구와 약관 본문 확인 |

## 3. 사용자가 직접 확인해야 하는 항목 (자동 검증 불가)

- 실제 브라우저에서 화면 배치와 시각 품질 (스크린샷 3장은 흐름 확인용)
- 실기기 공유 시트 동작
- 운영 SMTP 메일 발송
- 운영 DB 스키마와 마이그레이션 적용 여부 (읽기 전용 SQL 실행 필요)
- 약관 본문과 법적 고지 문구
- 독립 코드 리뷰 (현재 미완료)

## 4. 이력서·면접에 쓰기 전 확인 체크리스트

- [ ] 위 "사용자 결정" 칸의 내용이 실제로 본인이 한 판단과 일치하는지 확인했다
- [ ] "Claude Code 보조"로 적힌 코드를 본인이 읽고 설명할 수 있는지 확인했다
- [ ] 측정하지 않은 수치를 쓰지 않았다
- [ ] 미검증 항목(운영 DB, 운영 SMTP, 독립 리뷰, 약관 이력)을 한계로 함께 적었다
