### 1.3 가치 전달 (4관점)

| 관점 | 내용 |
|------|------|
| **문제** | 없는 경로·렌더 오류·미구현 메뉴에서 헤더 없는 흰 화면이나 전체 크래시가 나고, 대상 없는 링크가 반응 없으며, 760px 이하에서 메뉴로 이동할 수 없어 사용자가 길을 잃는다. 로그인 직후 가장 먼저 보이는 문제다. |
| **해결** | 페이지·최상위 두 곳의 ErrorBoundary로 렌더 오류를 잡아 오류 상황에서도 헤더·푸터를 유지하고, NotFound·ComingSoon 공통 화면으로 없는 경로와 미구현 기능을 구분해 안내하고, 모바일 햄버거·드로어로 760px 이하에서 모든 메뉴에 접근할 수 있게 했다. |
| **기능/UX 효과** | 어떤 URL·오류에서도 헤더를 통해 이동 가능. 사용자는 "페이지 없음" vs "아직 없음" vs "오류 발생"을 명확히 안내받음. 모바일에서도 주요 메뉴(여행지, 여행 즐기기, 피드, 회원 메뉴)에 접근 가능. 반응 없는 링크 0개(Layout 안 페이지·헤더·푸터·공지 기준). |
| **핵심 가치** | 로그인 직후 결함 해결로 사용자 신뢰도 향상. 다음 기능들(상세 페이지 fallback, 신규 화면)이 재사용할 공통 컴포넌트 마련. ErrorBoundary 범위 설계·드로어 접근성·포커스 트랩은 면접에서 설명 가능한 포인트. |

## 7. 회고 (Keep / Problem / Try)

### 7.1 잘한 점 (Keep)

- **이전 기능의 원칙 준수**: auth-token-flow의 합의 (CLAUDE.md 워크플로우, 에이전트 역할 분담)을 이번에도 그대로 적용해 frontend-lead(구현) → frontend-code-reviewer(리뷰) → bkit gap-detector(분석) → 완료 보고서 flow가 일관성 있게 진행됐다.
- **1회 반복으로 완성**: Check 1차 97.3% → Act-1 6건 수정 → Check 2차 99.0%로, 한 번의 반복으로 머지 가능 상태 달성.
- **설계 갱신으로 문서 정합**: D-1~D-19 구현 결정을 설계 v0.3에 모두 반영해 분석과 설계의 불일치가 없다.
- **공통 컴포넌트 재사용성**: NotFound·ComingSoon·StatusPage.css를 설계했으므로 다음 기능(상세 페이지 fallback, 신규 화면)에서 바로 쓸 수 있다.
- **접근성·포트폴리오 가치**: ErrorBoundary 범위 설계, 드로어 포커스 트랩, `#root` inert, 6가지 닫힘 경로는 기술 면접에서 설명할 만한 복잡도를 담고 있다.

### 7.2 문제점 (Problem)

- **백엔드 의존 항목**: 로그인 상태 드로어, 로그아웃 실패 알림, 복원 중 UI의 런타임 확인이 백엔드 서버 상태에 묶여 있다 (L2 #3, #9~#9-3). 다음에는 로컬 Mock이나 test 프로필로 미리 검증할 방법을 마련해야 한다.
- **제외 범위의 결함 잔존**: 계획 2.2에서 제외한 로그인·회원가입·비밀번호 찾기 페이지의 13개 `href="#"` 링크가 그대로 남아 있다. 범위 조정이 필요했지만 사전에 충분히 검토되지 않았다.
- **기존 문제의 발견**: 자동 L2 실행 중 `/enjoy` 콜라주 잘림(761~800px, 1101~1266px)이 발견됐으나 `98922ee` 이전부터 있던 문제라 후속으로 미뤄야 했다. 범위 외 관찰 항목과 기존 문제를 구분하는 절차가 필요하다.

### 7.3 다음 번에 시도할 것 (Try)

- **백엔드 Mock 준비**: 로그인 상태·로그아웃 실패 등의 시나리오를 test 프로필의 Mock 또는 커스텀 엔드포인트로 구성해 프론트 L2 독립 실행이 가능하게 한다.
