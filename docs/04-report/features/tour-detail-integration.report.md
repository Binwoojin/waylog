### 1.3 가치 전달 (4관점)

| 관점 | 내용 |
|------|------|
| **문제** | 홈의 "여행을 더 즐겁게"와 "이번 주 여행 소식" 카드가 TourAPI contentId(숫자)를 보내는데, 상세 페이지는 목업(slug)에서만 찾아서 **모든 홈 클릭이 잘못된 장소**를 보여 준다. 잘못된 id를 입력해도 조용히 다른 콘텐츠로 대체된다. |
| **해결** | 상세 id 해석 규칙을 "목업 id → 목업, 숫자 contentId → API 조회, 그 외 → not-found"로 변경했다. 백엔드는 없는 콘텐츠를 502가 아닌 404로 응답한다. 홈 카드 링크를 유형에 맞는 경로로 변경했고, 상세 간 이동 시 이전 상태가 남지 않도록 `key`로 재마운트한다. |
| **기능/UX 효과** | 사용자가 누른 홈 카드와 같은 장소가 상세에 표시된다. 없는 콘텐츠는 다른 장소 대신 "콘텐츠를 찾을 수 없습니다" 안내를 받는다. 페이지 이동 시 스크롤이 맨 위로 초기화되고, 저장·사진 위치 등 이전 상태가 남지 않는다. |
| **핵심 가치** | 앱의 가장 눈에 띄는 핵심 흐름(홈 → 상세)의 신뢰성을 복구한다. 목록은 아직 목업이라 한 번에 API로 전환할 수 없는 상황에서, 데이터 출처를 해석하는 점진적 전환 구조와 비동기 상태 머신(`useTourDetail`), 경쟁 조건 회피(`isActive` 플래그)는 포트폴리오와 기술 면접에서 설명 가능한 포인트다. |

### 7.1 잘한 점 (Keep)

- **PDCA 문서의 일관성**: app-safety-net의 합의(Plan→Design→Do→Check→Act→Report)를 그대로 따라 이전보다 더 체계적인 문서 추적이 가능했다.
- **빠른 문제 발견과 수정**: 1차 gap 분석 96.8% → Act-1 수정 → 2차 gap 분석 97.6%로, 두 번의 짧은 반복으로 거의 완성도 높게 도달했다. 코드 리뷰는 2차에서 MF-A 1건이 남았고, 수정 후 회귀 스크립트로 확인했다.
- **설계 문서의 세밀함**: 설계 v0.2(초안)에서 의도적 변경 8개, 추가 차이 9개를 발견했고, 모두 설계 v0.3~v0.4에 역반영해 문서 정확도를 높였다. 이번에 새 개발자가 와도 따라갈 수 있는 수준.
- **비동기 상태 관리의 안정성**: `isActive` 플래그로 늦은 응답을 차단하고, `status` 하나로 불가능한 상태 조합을 없앤 덕분에 id 변경 시 화면이 깜빡이거나 이전 데이터가 노출되지 않는다.
- **목업-API 혼합 구조의 유지보수성**: 해석 함수(`resolveDestinationDetail`)와 view model로 출처를 한곳에서 관리하므로, 목록이 API로 전환될 때 목업 분기만 삭제하면 된다.

### 7.2 문제점 (Problem)

- **실제 환경 검증 미흡**: 환경변수 `TOUR_API` 키가 없어 실제 TourAPI 응답(#5~#6)을 확인하지 못했다. G-02는 기술적으로는 허용되지만(없는 콘텐츠가 502 → 오류 카드 → 사용자는 다른 장소를 보지 않음), "정상 작동"을 완전히 증명하려면 필요하다.
- **L2 브라우저 수동 확인 미실행**: 로딩 live region(`role="status"`) 공지 여부(G-05), 360px 폭 검증(C-4), 스크린 리더(SI-2), 이미지 HTML 보임(G-08) 등 5개 항목이 아직 미검증이다. 자동화(Playwright)를 없이 수동 브라우저 여기에만 의존하고 있다.
- **연락처 링크 규칙의 복잡성**: `toTelHref`가 v0.2→v0.3→v0.3.1로 3번 수정되면서 로직이 복잡해졌다. 정규식의 범위·후보·숫자 세기가 얽혀 있고, 테스트 케이스(27개)로 검증하고 있지만 추가 입력까지 완전히 커버하기는 어렵다.

### 7.3 다음 번에 시도할 것 (Try)

- **CI 환경에서의 자동 L1 테스트**: 현재는 curl 9개를 수동으로 실행하고 있다. 백엔드의 로컬 프로필로 작동하는 `mvnw verify` 또는 `gradle test`에 L1 시나리오를 자동화하면 누락 위험이 줄어든다.
- **Playwright E2E 테스트 자동화**: §8.3 L2 체크리스트를 Playwright로 작성해 매번 수동 확인을 없앤다. 홈 카드 클릭, 상세 API 조회, 뒤로 가기, 오류 재시도 등의 흐름을 자동으로 검증한다.
- **전화번호 패턴의 선택적 적용**: 짧은 대표번호(`1330`, `02-120`) allowlist를 추가해 위험 최소화·유용성 사이의 균형을 정하고, 사용자 데이터로 검증한다.
- **mock 응답의 실제 데이터 캡처**: `local-mock` 프로필의 Mock 데이터를 실제 API 응답 구조로 채워(특히 `overview`의 `<br>`·`&nbsp;` 패턴) 개발 환경의 테스트 정확도를 높인다. 지금은 개발자 추측으로 만든 상태.
